# 元データからの移行手順

**原則**: 元データは**読むだけ**で、変更・削除・初期化はしません（移行前後で旧保存領域が同一であることをテストで確認）。取り込んだ分は**コピー**です。

## A. 旧アプリと同じ場所（同じオリジン）にある場合 — 自動検出

ブラウザの保存領域は「オリジン（`https://ホスト名:ポート`）」ごとに分かれます。旧アプリと ZeroStudio が**同じオリジン**にあるとき（例: `https://user.github.io/` 配下の別リポジトリ同士、または同じ `localhost:ポート`）は、旧データがそのまま見えます。

1. ZeroStudio の「ホーム」に「旧アプリの保存データが N 件見つかりました」と出ます（または **インポート／エクスポート → 旧アプリのデータを移行**）。
2. 検出結果（種類・件数・「新規／取り込み済み／コピーとして追加／取り込めない」）を確認します。
3. 「N 件をコピーして取り込む」を押します。

検出対象: `codelab.projects.v2`（Web作品）・`codelab.pixel.projects.v1`（ドット絵）・`lp.proj` / `lp.auto`（回路）・`lp.ml.proj` / `lp.ml.auto`（機械）・`lp.asm`（CPUプログラム）・IndexedDB `playground-zero`（Zero の作品と付随データ）。

- 2回実行しても**重複しません**（取り込み済みは「取り込み済み」）。旧側で編集した内容は「コピーとして追加」。
- Logic の保存は元々**名前がキー**で ID がありません。移行時に新しい ID を付与します（同名でも別の作品になります）。
- 壊れたデータは「取り込めない」と理由つきで報告し、他の取り込みは続行します。
- Zero の旧 IndexedDB の検出には `indexedDB.databases()` が必要です。使えないブラウザでは検出されないため、B の方法（バックアップ書き出し）を使ってください。

## B. 別の場所（別ドメイン・別のブラウザ・ファイル）にある場合 — 書き出して取り込む

旧アプリ側で書き出し、ZeroStudio の **インポート／エクスポート → インポート** に読み込ませます（ドラッグ＆ドロップ可）。

| 旧アプリ | 書き出し方 | 取り込み後 |
|---|---|---|
| CODE LAB | エクスポート → JSON | Code Studio / Web作品 |
| PIXEL LAB | JSON 出力 | Code Studio / ドット絵 |
| LOGIC PLAYGROUND 回路 | 「JSON出力」 | Logic Studio / 回路 |
| Machine Lab | 「JSON出力」 | Logic Studio / 機械 |
| CPU Lab | アセンブリ欄の内容をテキストエディターに貼り付け、`.asm` として保存（元アプリにファイル保存機能があるかは未確認） | Logic Studio / CPUプログラム |
| PLAYGROUND ZERO | 「バックアップ」の書き出し | Zero Engine（Zero 自身の検証・重複判定で取り込み。既存の作品は上書きされず、内容が違えば別IDの別作品） |

すべて**確認画面**（何が新規で何が重複か、取り込めない理由）を出し、「取り込む」を押すまで何も保存しません。

## C. ZeroStudio のバックアップから復元する

「全データのバックアップを書き出す」で作ったファイルを、同じ **インポート** で読み込みます。既存のプロジェクトは上書きされません。作品・素材・Zero の付随データ（お気に入りなど。**まだ無いものだけ追加**）が戻ります。

## 元データが安全かの確認方法

ブラウザの開発者ツール → Application → Local Storage / IndexedDB で、移行の前後に `codelab.*`・`lp.*`・`playground-zero` の内容が同じであることを確認できます。ZeroStudio 自身の保存先は `zs1:*` と `zerostudio-v1` です。
